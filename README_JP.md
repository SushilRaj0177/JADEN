# JADEN — 日本の住所データエンジニアリング＆正規化エンジン

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Typing: PEP 561](https://img.shields.io/badge/typing-PEP%20561-green.svg)](https://peps.python.org/pep-0561/)

**JADEN (Japanese Address Data Engineering & Normalization Engine)** は、日本の住所表記における構造的多様性、歴史的表記揺れ、および法的体系の違いを高精度かつ決定論的に解決するPython製住所正規化エンジンです。外部のブラックボックスWeb APIや有料ジオコーディングサービスに依存することなく、純粋なアルゴリズム（Prefix Trie、決定性有限オートマトン、Unicode文脈解析）により、**毎秒35,000件超**のオフライン高速処理を実現します。

*(English documentation is available at [README.md](README.md).)*

## 1. 日本の住所が抱える技術的課題

欧米型の「通り名＋番地」（例: `123 Main St, Suite 400`）とは異なり、日本の住所体系は歴史的・行政的に二重の法体系と独自の地域慣習を持っています。

```
┌──────────────────────────────────────────────────────────────────────────┐
│                      日本の住所における二重構造                          │
├─────────────────────────────────────┬────────────────────────────────────┤
│ 住居表示（街区方式）                │ 地番区域（不動産登記法）           │
│ （都市部: 東京23区、政令市など）    │ （地方部・未実施都市部）           │
├─────────────────────────────────────┼────────────────────────────────────┤
│ 都道府県 ──> 市区町村 ──> 町名      │ 都道府県 ──> 市区町村 ──> 大字     │
│ ──> 街区符号（〇番）                │ ──> 字 / 小字                      │
│ ──> 住居番号（〇号）                │ ──> 地番（〇番地） ──> 支号（枝番）│
└─────────────────────────────────────┴────────────────────────────────────┘
```

1. **二重の法的枠組み:**
   * **住居表示に関する法律（昭和37年法律第119号）:** 都市部の「街区方式」（街区符号［番］＋住居番号［号］）。
   * **不動産登記法（平成16年法律第123号）および民法:** 未実施区域における「地番」（大字・字＋番地＋枝番）。
2. **地域固有の空間座標システム:**
   * **京都市の通り名（公称町名との二重性）:** 「寺町通御池上る」のように、東西・南北の交差点からの相対位置を示す通り名表記。郵便・配送では不可欠ですが、公称登記町名とは分離して構造化する必要があります。
   * **北海道の碁盤目座標（条・丁目）:** 札幌市や旭川市などで用いられる東西南北のグリッド（例: 「北1条西2丁目」）。
3. **Unicodeハイフンの混沌と固有名詞の衝突:**
   * 日本語入力環境では10種類以上のダッシュ・ハイフン異体字（`-`, `－`, `‐`, `―`, `ー`, `～` など）が無秩序に混在します。
   * カタカナ長音符（`ー` / `U+30FC`）は、数字間ではハイフン（`1ー2ー3` $\to$ `1-2-3`）として機能する一方、カタカナ外来語（`タワー`, `センター`）では文字列の破壊を防ぐため厳密に維持する必要があります。
   * 地名そのものに漢数字が含まれる場合（`六本木`, `八王子`, `十条`, `四日市`, `三番町`）、安易な一括置換を行うと `6本木` や `4日市市` に誤変換される致命的な問題が発生します。

## 2. 4階層の事実分類（Taxonomy of Truth）

JADENは、推測と確定事実を混同しないため、抽出されたすべての構成要素を以下の4階層に厳密に分類します。

| 階層 | 名称 | 定義と具体例 |
| :--- | :--- | :--- |
| **Tier 1** | **法定・公的基準（Statutory）** | JIS X 0401（都道府県コード）、JIS X 0402（市区町村コード）、総務省 全国地方公共団体コード（モジュラス11検査数字）、街区符号（番）、住居番号（号）、地番（番地）、枝番。 |
| **Tier 2** | **公認地域慣習（Conventional）** | 京都市の通り名（上る・下る・東入・西入）、北海道の条丁目グリッド（北N条西M丁目）、標準的なハイフン省略記法（`6-10-1`）。 |
| **Tier 3** | **ヒューリスティック推定（Heuristic）** | 省略された都道府県の推定（例: `新宿区...` $\to$ `東京都`）、長音符とハイフンの文脈判別、スペース区切りのない建物名と階数・部屋番号の分離。 |
| **Tier 4** | **システム定義（System Artifact）** | JADENの正規化出力フォーマット、確信度スコア（0.0〜1.0）、JSONスキーマ構造。 |

## 3. アーキテクチャと処理パイプライン

```
                      生の日本語住所文字列
                               │
                               ▼
   [Stage 1: 文脈考慮型テキスト前処理・Unicode正規化]
   • Unicode NFKC正規化（全角英数の半角化）
   • カタカナ長音符（U+30FC）の文脈判定（数字間のみハイフン化、タワー等は保持）
   • 無条件ダッシュ記号（U+2010〜2015, U+FF0D, 全角チルダ等）の統一
                               │
                               ▼
   [Stage 2: 街区限定 漢数字・アラビア数字変換]
   • 丁目・番地・号の漢数字のみを変換（「三丁目」->「3丁目」）
   • 否定先読み（Negative Lookahead）により「三番町」「一番町」などの固有名詞を保護
                               │
                               ▼
   [Stage 3: 行政区画 PrefixTrie 解析エンジン]
   • 全47都道府県（JIS X 0401）のO(L)プレフィックス照合
   • 市区町村・政令市行政区（JIS X 0402）の最長一致照合
   • 全国地方公共団体コード（6桁）の付与とモジュラス11検証
   • 都道府県省略時の自動逆引き推定
                               │
                               ▼
   [Stage 4: 地域慣習文法パーサー]
   • 京都通り名解析器: 交差点名および進行方向（上る/下る/東入/西入）を分離
   • 北海道条丁目解析器: 方位グリッド座標（北N条西M丁目）の抽出
                               │
                               ▼
   [Stage 5: 街区・地番 決定性有限オートマトン (BlockFSM)]
   • 丁目・番・号（街区方式）および番地・枝番（地番方式）の決定論的抽出
   • ハイフン表記（`6-10-1`）と漢字表記（`6丁目10番1号`）の双方に対応
                               │
                               ▼
   [Stage 6: 建物名・階数・部屋番号 構造分離器]
   • 建物名末尾の階数（50F, 3階, B1F）および部屋番号（301号室）を特定・分離
                               │
                               ▼
                 正規化済み NormalizedAddress オブジェクト
```

## 4. 準拠規格およびデータ出典

JADENに組み込まれているデータおよびアルゴリズムは、以下の公的規格・公表資料に基づいて検証されています。

1. **都道府県コード:** **JIS X 0401:1973（2014年改正）**（01 北海道 〜 47 沖縄県）
2. **市区町村コード:** **JIS X 0402:2020** および **総務省 全国地方公共団体コード仕様**
   * 5桁のJISコードに対し、モジュラス11（Modulus 11）方式で第6位の検査数字を算出・検証:
     $$\text{Sum} = \sum_{i=1}^{5} d_i \times w_i, \quad W = [6, 5, 4, 3, 2]$$
     $$R = \text{Sum} \pmod{11}$$
     $$\text{検査数字} = \begin{cases} (11 - R) \pmod{10} & (R \le 1) \\ 11 - R & (R \ge 2) \end{cases}$$
3. **住居表示基準:** **住居表示に関する法律（昭和37年法律第119号）**
4. **アドレス・ベース・レジストリ:** **デジタル庁 アドレス・ベース・レジストリ データ解説書（2024〜2025年版）**

## 6. インストールと利用方法

### インストール

```bash
git clone https://github.com/SushilRaj0177/JADEN.git
cd JADEN
pip install -e .
```

### Python ライブラリとしての利用

```python
import jaden

# 実世界の複雑な住所文字列を正規化
result = jaden.normalize("東京都港区六本木6-10-1六本木ヒルズ森タワー50F")

print(result.canonical)
# 出力: 東京都港区六本木6丁目10番1号 六本木ヒルズ森タワー 50F

print(result.components.lg_code)
# 出力: 131032 (港区の全国地方公共団体コード)

print(result.components.chome, result.components.ban, result.components.go)
# 出力: 6 10 1

print(result.components.building, result.components.floor)
# 出力: 六本木ヒルズ森タワー 50F

print(result.confidence_score)
# 出力: 1.0 (決定論的完全一致)
```

### 京都市の通り名住所の解析

```python
result = jaden.normalize("京都府中京区寺町通御池上る上本能寺前町488番地")

print(result.canonical)
# 出力: 京都府京都市中京区寺町通御池上る上本能寺前町488番地

# 通り名と登記町名の分離
print(result.components.kyoto_direction)
# 出力: KyotoDirectionClause(street_1='寺町通', street_2='御池', direction='上る', cardinal='north', raw_clause='寺町通御池上る')

print(result.components.town)
# 出力: 上本能寺前町

print(result.components.banchi)
# 出力: 488
```

### CLI（コマンドラインツール）としての利用

```bash
# 単一住所の解析（整形JSON出力）
jaden "東京都港区六本木6-10-1六本木ヒルズ森タワー50F"

# 正規化文字列のみを出力
jaden -c "新宿区西新宿2-8-1東京都庁 第一本庁舎"
# 出力: 東京都新宿区西新宿2丁目8番1号 東京都庁 第一本庁舎

# パイプラインでのストリーミング一括処理（JSON Lines形式）
cat input_addresses.txt | jaden --jsonl > output_normalized.jsonl
```

## 8. 動作限界および前提条件の明示

工学的誠実性の原則に基づき、JADENの対応範囲と制限事項を明記します。
1. **緯度経度座標・ポリゴンデータの非保持:** JADENは文字列データエンジニアリングおよび住所構造化エンジンであり、GIS用のポリゴン座標データは内蔵していません。
2. **同名自治体の都道府県省略時の曖昧性:** 都道府県名が省略され、かつ全国に複数存在する自治体名（例: 東京都と広島県の「府中市」、北海道と福島県の「伊達市」）の場合、決定論的正確性を保つために都道府県の明示が必要です。
3. **民間ビル名の構文的推定:** 民間ビル名やフロア・部屋番号の分離は構文ヒューリスティック（Tier 3）に基づきます（全国の民間建築物名称に関する法的レジストリが存在しないため）。
