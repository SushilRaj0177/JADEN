# JADEN — 日本の住所データエンジニアリング＆正規化エンジン

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Typing: PEP 561](https://img.shields.io/badge/typing-PEP%20561-green.svg)](https://peps.python.org/pep-0561/)

**JADEN (Japanese Address Data Engineering & Normalization Engine)** は、日本の住所表記における構造的多様性、歴史的表記揺れ、および法的体系の違いを高精度かつ決定論的に解決するPython製住所正規化エンジンです。外部のブラックボックスWeb APIや有料ジオコーディングサービスに依存することなく、決定性アルゴリズム（Prefix Trie、有限オートマトン、Unicode文脈解析）により、多様な実住所コーパスに対して**毎秒約3,000件**の完全オフライン高速処理（ヒープメモリ約3.6MB）を実現します。

*(English documentation is available at [README.md](README.md).)*

## 1. 日本の住所が抱える技術的課題

欧米型の「通り名＋番地」（例: `123 Main St, Suite 400`）とは異なり、日本の住所体系は歴史的・行政的に二重の法体系と独自の地域慣習を持っています。

```
┌──────────────────────────────────────────────────────────────────────────┐
│                      日本の住所における二重構造                          │
├─────────────────────────────────────┬────────────────────────────────────┤
│ 住居表示（街区方式）                │ 地番区域（不動産登記法）           │
│ （都市部: 東京23区、政令市など）    │ （地方部・未実施都市部）           │
├─────────────────────────────────────┼────────────────────────────────────┤
│ 都道府県 ──> 市区町村 ──> 町名      │ 都道府県 ──> 市区町村 ──> 大字     │
│ ──> 街区符号（〇番）                │ ──> 字 / 小字                      │
│ ──> 住居番号（〇号）                │ ──> 地番（〇番地） ──> 支号（枝番）│
└─────────────────────────────────────┴────────────────────────────────────┘
```

1. **二重の法的枠組み:**
   * **住居表示に関する法律（昭和37年法律第119号）:** 都市部の「街区方式」（街区符号［番］＋住居番号［号］）。
   * **不動産登記法（平成16年法律第123号）および民法:** 未実施区域における「地番」（大字・字＋番地＋枝番）。
2. **地域固有の空間座標システム:**
   * **京都市の通り名（公称町名との二重性）:** 「寺町通御池上る」のように、東西・南北の交差点からの相対位置を示す通り名表記。京都市中心部の通り名には「東洞院通」「西洞院通」「下立売通」「上長者町通」のように東西南北や上下の方位文字を含む通りが多く存在し、単純な除外文字正規表現では破壊されます。
   * **北海道の碁盤目座標（条・丁目）:** 札幌市や旭川市などで用いられる東西南北のグリッド（例: 「北1条西2丁目」）。
3. **Unicodeハイフンの混沌と固有名詞の保護:**
   * 日本語入力環境では10種類以上のダッシュ・ハイフン異体字（`-`, `－`, `‐`, `―`, `ー`, `～` など）が無秩序に混在します。
   * カタカナ長音符（`ー` / `U+30FC`）は、数字間ではハイフン（`1ー2ー3` $\to$ `1-2-3`）として機能する一方、カタカナ外来語（`タワー`, `センター`）では文字列の破壊を防ぐため厳密に維持する必要があります。
   * 地名や商店街、施設名に数字・番が含まれる場合（`六本木`, `八王子`, `十条`, `四日市`, `三番町`, `一番街`, `麻布十番`, `一番館`）、安易な漢数字変換を行うと `1番 街` や `麻布10番` に誤変換される致命的な問題が発生します。
4. **都道府県省略時の自治体名衝突:**
   * 日本全国で同一の市区町村・行政区名を持つ自治体は38存在します（例: `中央区` は東京特別区および政令指定都市10区の計11自治体、`府中市` は東京都と広島県、`伊達市` は北海道と福島県）。都道府県が省略された入力に対し、根拠なく東京都と即断することは許されず、不確実性を `is_ambiguous=True` および候補一覧として明示する必要があります。

## 2. 4階層の事実分類（Taxonomy of Truth）

JADENは、推測と確定事実を混同しないため、抽出されたすべての構成要素を以下の4階層に厳密に分類します。

| 階層 | 名称 | 定義と具体例 |
| :--- | :--- | :--- |
| **Tier 1** | **法定・公的基準（Statutory）** | JIS X 0401（都道府県コード）、JIS X 0402（市区町村コード）、総務省 全国地方公共団体コード（モジュラス11検査数字）、街区符号（番）、住居番号（号）、地番（番地）、枝番、大字、字。 |
| **Tier 2** | **公認地域慣習（Conventional）** | 京都市の通り名（上る・下る・東入・西入）、北海道の条丁目グリッド（北N条西M丁目）、標準的なハイフン省略記法（`6-10-1`）。 |
| **Tier 3** | **ヒューリスティック推定（Heuristic）** | 省略された都道府県の推定、長音符とハイフンの文脈判別、スペース区切りのない建物名と階数・部屋番号の分離。 |
| **Tier 4** | **システム定義（System Artifact）** | JADENの正規化出力フォーマット、確信度スコア（0.0〜1.0）、JSONスキーマ構造。 |

## 3. アーキテクチャと処理パイプライン

```
                      生の日本語住所文字列
                               │
                               ▼
   [Stage 1: 文脈考慮型テキスト前処理・Unicode正規化]
   • Unicode NFKC正規化（全角英数の半角化）
   • カタカナ長音符（U+30FC）の文脈判定（数字間のみハイフン化、タワー等は保持）
   • 無条件ダッシュ記号（U+2010〜2015, U+FF0D, 全角チルダ等）の統一
                               │
                               ▼
   [Stage 2: 街区限定 漢数字・アラビア数字変換]
   • 丁目・番地・号の漢数字のみを文脈限定で変換（「三丁目」->「3丁目」）
   • 固有名詞防衛パターンにより「一番街」「麻布十番」「三番町」を完全保護
                               │
                               ▼
   [Stage 3: 行政区画 PrefixTrie 解析エンジン]
   • 全47都道府県（JIS X 0401）のO(L)プレフィックス照合
   • 1,918市区町村・行政区（JIS X 0402 / 総務省団体コード）の最長一致照合
   • 都道府県省略時の衝突検出（中央区、府中市、伊達市等の候補提示）
   • 未知の外国文字列・無効文字列の拒絶ガード
                               │
                               ▼
   [Stage 4: 地域慣習文法パーサー]
   • 京都通り名解析器: 方位文字含有通り（東洞院通、下立売通等）に対応した二段階交差点構文解析
   • 北海道条丁目解析器: 方位グリッド座標（北N条西M丁目）の抽出
                               │
                               ▼
   [Stage 5: 街区・地番 決定性有限オートマトン (BlockFSM)]
   • 大字（Oaza）・字（Koaza）の自動分離
   • 法定住所体系（gaiku_hoshiki / chiban / unspecified）の自動判別
   • 地番区域ではハイフン数字を番地・枝番にマッピング
                               │
                               ▼
   [Stage 6: 建物名・階数・部屋番号 構造分離器]
   • 建物名末尾の階数（50F, 3階, 地下1階, B2F）および部屋番号（301号室, 301）を特定・分離
                               │
                               ▼
                 正規化済み NormalizedAddress オブジェクト
```

## 4. 準拠規格およびデータ出典

JADENが内包するすべての行政コードおよび規格値は、公的機関の公表データに基づき検証されています。

1. **都道府県コード (JIS X 0401:1973 / 2014年改正):**
   * 47都道府県（`01` 北海道 〜 `47` 沖縄県）。官報および規格票に基づく検証済み。
2. **全国地方公共団体コード (JIS X 0402:2020 & 総務省仕様):**
   * **提供元機関:** 総務省自治行政局
   * **典拠ファイル:** 都道府県コード及び市区町村コード（令和6年1月1日更新）
   * **公式URL:** `https://www.soumu.go.jp/main_content/000925835.xlsx`
   * **SHA256ハッシュ:** `7d04c8a7f6a6e76a7823a0414a8422bf2b26bb6070766971df76eab58ea6ff78`
   * **収録団体数:** **1,918件**（令和6年1月1日 浜松市の行政区再編を反映）
     - 47都道府県
     - 1,747市区町村: 特別区23、政令指定都市20、一般市772、町743、村189（北方領土6村を含む）
     - 171行政区（政令指定都市内の区）
   * **検査数字検証:** 収録されたすべてのコードが総務省公式モジュラス11アルゴリズムに100%適合。
     $$\text{Sum} = \sum_{i=1}^{5} d_i \times w_i, \quad W = [6, 5, 4, 3, 2]$$
     $$R = \text{Sum} \pmod{11}$$
     $$\text{Check Digit} = \begin{cases} (11 - R) \pmod{10} & \text{if } R \le 1 \\ 11 - R & \text{if } R \ge 2 \end{cases}$$
3. **住所関連法令:**
   * *住居表示に関する法律（昭和37年法律第119号）*: 街区方式（丁目・番・号）。
   * *不動産登記法（平成16年法律第123号）*: 地番区域（大字・字・番地・枝番）。
4. **デジタル庁 アドレス・ベース・レジストリ:**
   * JADENは町字・街区・地番の概念モデルに準拠しています。なお、数ギガバイトに及ぶ空間ポリゴン境界データは軽量オフラインエンジンとしての設計思想に基づき内包していません。

## 6. インストールと利用方法

### インストール

```bash
git clone https://github.com/SushilRaj0177/JADEN.git
cd JADEN
pip install -e .
```

### Python API

```python
import jaden

# 1. 都市部住居表示（ビル名・階数付き）
res1 = jaden.normalize("東京都港区六本木6-10-1六本木ヒルズ森タワー50F")
print(res1.canonical)
# 出力: 東京都港区六本木6丁目10番1号 六本木ヒルズ森タワー 50F
print(res1.components.lg_code)        # '131032' (港区)
print(res1.components.address_regime) # 'gaiku_hoshiki'

# 2. 地方部地番表記（大字・字・地番・枝番）
res2 = jaden.normalize("長野県長野市大字南長野字幅下692-2")
print(res2.components.oaza)            # '南長野'
print(res2.components.koaza)           # '幅下'
print(res2.components.banchi)          # 692
print(res2.components.edaban)          # 2
print(res2.components.address_regime)   # 'chiban'

# 3. 京都市通り名表記
res3 = jaden.normalize("京都府中京区御池通東洞院東入笹屋町436")
print(res3.components.kyoto_direction.street_1)  # '御池通'
print(res3.components.kyoto_direction.street_2)  # '東洞院'
print(res3.components.kyoto_direction.direction) # '東入'
print(res3.components.banchi)                    # 436 (地番)

# 4. 都道府県省略時の曖昧性検出
res4 = jaden.normalize("府中市宮西町2-24")
print(res4.components.is_ambiguous)          # True
print(res4.components.ambiguous_candidates)  # ('東京都府中市 (132063)', '広島県府中市 (342084)')
print(res4.confidence_score)                 # 0.50
```

### コマンドラインインターフェース (CLI)

```bash
# 単一住所の正規化（構造化JSON出力）
jaden "東京都港区六本木6-10-1六本木ヒルズ森タワー50F"

# 正規化文字列のみの出力
jaden -c "新宿区西新宿2-8-1東京都庁 第一本庁舎"
# 出力: 東京都新宿区西新宿2丁目8番1号 東京都庁 第一本庁舎

# JSON Lines ストリーミング一括処理
cat addresses.txt | jaden --jsonl > normalized.jsonl
```

## 8. システムの境界と制限事項（Limitations）

設計の透明性を担保するため、JADENの技術的限界を明記します。
1. **空間ポリゴン・緯度経度の非保持:** JADENはテキストデータ正規化エンジンであり、数GBに及ぶGISポリゴンシェープファイルや緯度経度座標は内包していません。
2. **同名自治体の都道府県省略時の曖昧性:** 都道府県が省略され、同名の自治体が存在する場合（例: `中央区`, `府中市`, `伊達市`）、推測による即断を行わず `is_ambiguous=True` として候補を出力します。
3. **民間建物名の構文的推定:** 民間商業ビルの公的全国台帳は存在しないため、建物名および部屋番号は構文規則（Tier 3）による推定です。
4. **ハイフンのみ表記における街区と地番の判別限界:** `丁目` や `大字`、`番地` などの語句がなく、単に `町名 1-2` と書かれている場合、公図境界データなしには街区方式か地番かを決定できないため、`address_regime="unspecified"` として扱います。
